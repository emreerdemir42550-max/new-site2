What EXIF metadata reveals about you — and what removing it does not fix

A photo can carry the camera, the timestamp, the serial number and the exact coordinates. What each field means, how to read it, and the limits of stripping it.

Short answer: EXIF is a metadata block that cameras and phones write into image files. It commonly includes the device model, the capture time, exposure settings and — if location services were on — GPS coordinates with enough precision to identify a building. Removing it means re-encoding the image without that block, which also changes the pixels slightly.

What is actually in there

The Exif specification defines a set of tags grouped into IFDs (image file directories). The ones that matter for privacy are a small subset:

Make, ModelCamera or phone modelLinks photos from the same device
DateTimeOriginalCapture timestamp to the secondPlaces a person at a time
GPSLatitude, GPSLongitudeCoordinates in degrees/minutes/secondsOften accurate to a few metres
GPSAltitude, GPSTimeStampHeight and UTC time of the fixConfirms the reading is real
SerialNumber, BodySerialNumberDevice serialTies files to one physical unit

OrientationHow to rotate for displayNot private, but affects output

Phones are the usual culprit. A camera with no GPS writes none, while a phone with location permission writes a full fix — and many messaging apps strip it on send, which is why people are often surprised when a file they saved locally still has coordinates.

Reading it before you decide

The useful habit is to look first and delete second. Remove Image Metadata parses the file in the tab, lists the recognised fields, and gives GPS its own warning line rather than folding it into a generic “metadata” count. If there is no GPS, you can see that too — the absence is information.

Two details about reading EXIF correctly:

  • Timestamps are usually local time with no timezone. The spec has an offset tag, but many devices omit it. Do not assume a UTC value.
  • GPS is stored as rational numbers, not decimal degrees. A parser converts them; a naive one gets the sign or the minute division wrong, which can put a location in the wrong hemisphere.

Why removing it changes the pixels

There are two ways to strip metadata:

  1. Container rewrite. Remove the APP1/EXIF segment from the JPEG and keep the compressed image data untouched. Lossless, fast, and requires a format-specific writer for each file type.
  2. Re-encode. Decode the image to pixels, draw it to a canvas, and encode a new file. The new file has no EXIF because the encoder does not write one — but the pixels have been through a decode/encode cycle.

Browser tools use the second approach, because Canvas is the only general-purpose encoder available. The practical consequences:

  • Quality drops slightly in lossy formats. One extra generation, not a catastrophic one, but real.
  • Orientation is baked in. A photo taken sideways stores Orientation: 6 and expects the viewer to rotate it. createImageBitmap applies that orientation by default, so the re-encoded image is upright with no orientation tag. This is usually what you want; it is worth knowing that it happened.
  • Colour profile is re-derived. A wide-gamut source becomes sRGB.

If a tool claims lossless EXIF removal in a browser without a format-specific writer, be sceptical.

What removal does not fix

  • Pixels. A reflection in a window, a street sign, a name badge — those stay. Metadata removal is not redaction.
  • File names. IMG_20260910_143012.jpg is itself a timestamp. Rename as well.
  • Filesystem timestamps. Creation and modification times on your own disk are outside the file.
  • Thumbnails inside other containers. Some formats embed a preview image with its own metadata; a full re-encode drops it, but a partial tool may not.
  • Already-published copies. If the file was uploaded somewhere, removing metadata locally does not touch the copy that is already there.

A workable routine

  1. Read the metadata and check for GPS.
  2. If the photo is going somewhere public, strip it — and rename the file.
  3. If the image will be edited further, strip metadata at the end of the edit, not before.
  4. Keep an unmodified original if the photo has archival value.

FAQ

Does every photo have EXIF? No. Screenshots, exports from design tools and images that have already been re-encoded often have none.

Is EXIF the same as IPTC or XMP? No. They are separate metadata families that can coexist in one file. A cleaner aimed at EXIF may leave XMP untouched.

Can I remove only GPS? Not with a canvas re-encode — the whole block goes. Field-selective removal needs a format-aware writer.

Does social media strip it? Most large platforms do on upload, but you should not rely on that for a file you are sending directly.
