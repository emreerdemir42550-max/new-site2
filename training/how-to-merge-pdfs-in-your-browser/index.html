How to merge PDFs without uploading them

What a PDF merge actually does to the page tree, why page order is the only decision that matters, and why encrypted files refuse to merge locally.

The tool behind this article

Short answer: a merge copies the page objects of several documents into one new document, in the order you choose. Nothing is re-rendered, so text stays selectable and images keep their original encoding. You can do it in a browser tab with Merge PDF, and the file never has to leave your device.

What a merge actually changes

A PDF is not a flat sequence of pages. It is a tree of objects: a catalogue points at a page tree, the page tree lists page objects, and each page object references its content stream, its fonts and its images. Merging means creating a new document and appending references to page objects that already exist in the source files.

That detail explains most of the behaviour people notice:

  • Quality does not change. Pages are copied as objects, not rasterised, so a merged PDF looks exactly like its sources.
  • Page sizes can differ inside one file. A4 pages and Letter pages can coexist, because each page object carries its own MediaBox.
  • File size grows roughly by the sum of the inputs. Shared fonts are not deduplicated across documents in a naive merge.

Page order is the only real decision

Because the output is an ordered list of page objects, the order of the input files is the order of the pages. That sounds trivial, but it is the part people get wrong: they merge first and then try to fix the order afterwards, which means a second operation and a second chance to introduce a mistake.

A better workflow is to decide the packet order before pressing merge:

  1. Cover or routing sheet.
  2. The primary document, in its own order.
  3. Appendices and attachments.
  4. Anything that needs to be found last — signature pages, schedules, forms.

In Merge PDF the file list is the page order. Each row shows the page count it contributes, so a 3-page file that should be 30 pages is visible before you commit.

Doing it locally, step by step

  1. Open the tool. The page loads a small JavaScript module; no file has been read yet.
  2. Choose two or more PDFs. Each file is read as an ArrayBuffer through the File API and parsed by PDF-lib in the tab.
  3. Reorder the list. Drag a row, or focus it and use the arrow buttons — the keyboard path produces the same result.
  4. Press merge. PDF-lib creates a new document and copies each page in list order.
  5. Download the result. The Blob is created in memory and saved by the browser.

If you want to confirm that nothing was uploaded, open DevTools → Network, clear the list, then merge. There is no request carrying file bytes. That is the whole verification.

Why some PDFs refuse to merge

An encrypted PDF stores its page tree behind an encryption dictionary. Reading the pages requires the password, and the document may also restrict copying. PDF-lib will throw rather than produce a partially valid file, and the tool reports the file as unsupported.

That is the honest outcome. Guessing passwords, or silently dropping an encrypted input, would both be worse: the first is not a feature, and the second produces a document that looks complete and is not.

The same logic applies to damaged files. A truncated PDF may parse far enough to report a page count and then fail mid-copy. If that happens, the tool reports the error instead of handing you a file with missing pages.

Limitations worth knowing before you start

  • Digital signatures break. A signature covers the exact bytes of the original file. Any merge creates new bytes, so the signature no longer matches. If a signed document must stay verifiable, merge around it rather than through it.
  • Document-level attachments stay behind. Embedded files belong to the document catalogue, not to a page, so they are not carried into the merged output.
  • Bookmarks are not rebuilt. Named destinations that point at page objects still resolve, but the outline tree is not merged into a new hierarchy.
  • Memory is finite. Each source document must be parsed at once. A handful of large scans can exhaust a tab, which is why the tool warns above a conservative size threshold rather than promising unlimited input.

When merging is the wrong tool

If you need one file that contains several documents as documents — each with its own name, description and metadata — a PDF portfolio is the closer fit. If you need to remove pages rather than add them, use Split PDF or Extract PDF Pages. And if the goal is a smaller file rather than a combined one, merging will only make it bigger.

FAQ

Does merging reduce image quality? No. Image streams are referenced, not re-encoded.

Can I merge files of different page sizes? Yes. Each page keeps its own dimensions.

What happens to form fields? Standard AcroForm fields are carried with their pages, but fields with the same name from different documents are not automatically reconciled into one logical form.

Is there a file count limit? No fixed number. The practical limit is available memory, which is why the tool reports total pages before you run it.
