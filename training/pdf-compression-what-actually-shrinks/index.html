What PDF compression actually shrinks — and what it costs

Stream filters, image re-encoding and page rasterisation are three different things that all get called 'compress'. Only one of them is lossless, and most online tools quietly use the third.

Editorial Team · 10 September 2026 · 4 min read

Short answer: a PDF gets smaller in one of three ways — better stream compression (lossless), re-encoding embedded images (lossy, text survives), or rasterising whole pages into images (lossy, text stops being text). Most “compress PDF” buttons do the third without saying so.

Where the bytes actually are

A PDF is a set of objects. The bulk of a typical file is in:

  • Image XObjects. Each embedded image is a stream, usually already JPEG or JPEG2000-compressed.
  • Content streams. The drawing instructions for each page. These compress well with Flate (zlib).
  • Fonts. Subset font programs, sometimes several hundred kilobytes each.
  • Object overhead. Cross-reference tables, page tree nodes, metadata.

The composition tells you what a given technique can achieve. A 40 MB scan is almost entirely image data; compressing its content streams saves almost nothing. A 40 MB CAD export may be mostly vector instructions that Flate can shrink substantially.

Technique 1 — lossless stream optimisation

Every stream in a PDF can carry a filter: /FlateDecode for zlib, /DCTDecode for JPEG data, /CCITTFaxDecode for fax-style bitonal images, and so on. Lossless optimisation:

  • re-compresses uncompressed streams with Flate;
  • uses object streams and cross-reference streams (PDF 1.5+) to remove per-object overhead;
  • removes unused objects and duplicate resources;
  • drops unreferenced metadata.

Nothing visual changes. Text stays text, images stay bit-identical. Savings depend entirely on how inefficiently the producer wrote the file — a badly generated PDF can halve; an already-optimised one barely moves.

Technique 2 — re-encoding embedded images

Here the images inside the document are decoded, downsampled, re-compressed at a chosen quality, and written back. Text and vector graphics are untouched, so the page still selects and searches normally.

This is the sweet spot for scans: a 600 dpi bitonal page re-encoded at 200 dpi JPEG is dramatically smaller and still readable on screen. The risk is over-doing it — thin strokes in small type are exactly what JPEG quantisation destroys first.

A proper implementation lets you choose the resolution and quality, and tells you what it did per image. A tool that only offers a single “compress” button is hiding a decision you should be making.

Technique 3 — page rasterisation

The nuclear option: render each page to a bitmap at some scale, then build a brand-new PDF whose pages each contain one image.

What it buys: predictable, often large size reductions, and it flattens anything complicated (forms, transparency, layers, embedded fonts).

What it costs:

  • Text is no longer text. Selection, search, copy, screen-reader access and text extraction all stop working.
  • Vector sharpness is gone. Lines that were mathematically crisp become pixels, which is visible when zoomed or printed.
  • Links and annotations disappear unless the rebuild explicitly recreates them.
  • Fonts are gone, so the file no longer carries its typography.

Compress PDF on this site uses this technique — and says so on the tool page, in the control label (“Compress (re-render pages)”), and in the result panel. That is the minimum honesty bar: if the output is images, the button should not pretend otherwise.

Why “it got bigger” happens

Compression is not monotonic. Re-encoding an already-optimised JPEG at high quality can produce a larger stream. Rasterising a text-heavy page at 2× scale can produce a much larger file than the original. A tool that reports the real before/after numbers lets you discard a bad result; a tool that shows a green “Done!” does not.

The result panel in this site’s compressor prints the before size, the after size and the percentage change — including a negative percentage, in red, when the file grew.

Practical advice

  • Keep the original. Compression is a derivative operation. Never overwrite your only copy.
  • Check the output, not the number. Open the compressed file and zoom in on the smallest text.
  • Do not chain compressors. Each lossy pass compounds.
  • Split before compressing if only a few pages are heavy — Split PDF plus targeted compression beats compressing everything.

FAQ

Is PDF compression always lossy? No. Stream optimisation is lossless. Image re-encoding and rasterisation are not.

Why did my text disappear? Because the tool rasterised the pages. The characters are now pixels.

Can I compress and keep the text layer? Yes, if the tool re-encodes images rather than pages. That requires a real PDF writer, not a renderer.

Does compression remove metadata? Usually not, unless the tool rebuilds the document. Use PDF Metadata Viewer & Cleaner for that separately.
