Merge vs portfolio vs attachment: three ways to bundle documents

Combining files into one PDF is not the only option, and sometimes it is the wrong one. How a merge, a portfolio and an embedded attachment differ in structure and in practice.

Short answer: a merge produces one continuous document with one page sequence. A portfolio keeps the files separate inside a container and presents them as a list. An attachment hides a file inside a host document. They solve different problems, and only the first one gives you continuous page numbers.

Merging: one document, one page sequence

A merge copies page objects from several documents into a new one. The result is a single PDF with a single page count. That is what you want when:

  • the output must print as one packet;
  • page numbers must run continuously;
  • a reader should move from one section to the next by scrolling;
  • the file will be reviewed as a whole, not as a set of parts.

It is the wrong choice when the individual files matter as files — a spreadsheet, an image, a video, a .docx. Those do not become pages without a conversion, and a conversion is a lossy re-interpretation.

Portfolios: a container that keeps files intact

A PDF portfolio uses the Collections feature (PDF 1.7, §12.3). The file has a normal page — usually a cover or an instructions page — plus an embedded file specification for each item. Viewers that understand collections show a file browser instead of pages.

The important property: each item keeps its original format and bytes. A portfolio can contain a PDF, a JPEG, a spreadsheet and a video, and each one opens in its own application.

What you give up:

  • No continuous pagination. There is no “page 14” across the whole bundle.
  • Viewer support varies. Some mobile readers show only the cover page and ignore the collection.
  • Printing is awkward — you print individual items, not the container.
  • Accessibility is weaker, because the file list is a viewer UI rather than document content.

Attachments: a file inside a file

An embedded file stream (§7.11.4) can be attached to a document or to a specific page. It appears in the viewer’s attachments panel and can be extracted later.

This is the right pattern for supporting material that belongs with a document but is not part of it: the source spreadsheet behind a report, the original scan behind a cleaned-up PDF, a signed receipt behind an invoice.

It is a bad pattern for content the reader is supposed to read, because many readers never open the attachments panel at all. If a document says “see attached appendix”, a meaningful fraction of recipients will never find it.

What this means for a browser tool

Merging is the operation a browser can do faithfully, because it only needs to copy page objects — no rendering, no format conversion, no embedding of foreign file types. Merge PDF does exactly that and nothing else.

Portfolios and attachments are possible in principle but need a writer that supports file specifications and the collection dictionary. pdf-lib exposes attachment APIs; a portfolio UI is a viewer feature you cannot guarantee. Shipping a “portfolio” that only some readers display is a support problem disguised as a feature, which is why this site does not offer one.

Practical decision guide

  • Contract + annexes, to be signed as a packet → merge, then add page numbers.
  • Application pack with a form, a scan and a spreadsheet → portfolio, or a ZIP if the recipient is not a PDF person.
  • Report with a data appendix for audit → merge the readable parts, attach the source data.
  • Several documents that will be edited later → do not merge. Send separate files, or a ZIP.

FAQ

Can I merge a Word document into a PDF? Not directly. It has to be converted to PDF first, and that conversion is a layout reconstruction with its own fidelity problems.

Does a merge keep bookmarks? Named destinations that point at copied pages still resolve, but the outline tree is not rebuilt into a new hierarchy.

Can I undo a merge? Yes — Split PDF with the original page ranges, or Extract PDF Pages for specific pages. Keep the sources until you are sure.

Is a ZIP better than a portfolio? For recipients outside a document workflow, usually yes. A ZIP opens everywhere and needs no special viewer.
