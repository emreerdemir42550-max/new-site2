01 / The stack

A pile of paper becomes a working index

The same page tree that makes a PDF hard to edit is what makes it fast to rearrange: pages are objects, and objects can be copied, dropped and reordered without touching a single pixel.

01 Merge PDF Drag files into order, then merge them into a single PDF. 02 Split PDF Cut a document into ranges, or explode it into single pages. 03 Reorder PDF Pages Put pages in the right order, with a keyboard path for every move. 04 Extract PDF Pages Pick the pages you need and drop the rest.

02 / The boundary

Your file enters memory. The network line stays flat.

A file you pick is a pointer to bytes on your disk. JavaScript reads those bytes into the tab, works on them there, and builds a new Blob for you to save. The request counter below is the honest diagram of that: nothing leaves.

08 / Verification

Don't trust the claim. Check it.

Every privacy statement on this site can be tested in about thirty seconds with tools you already have.

Read the methodology →
  1. 01
    Open the Network tab

    Clear it, run any tool, watch for a request that carries your file. There is none.

  2. 02
    Pull the plug

    Disable the network after the page loads. The tools still complete, because nothing depended on a connection.

  3. 03
    Read the libraries

    PDF-lib and PDF.js are public. The engines are small modules that call them directly — no hidden endpoint.
