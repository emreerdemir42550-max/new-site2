How local processing works

A file you choose is read into this browser tab, transformed by JavaScript, and handed back as a download. This page explains exactly what that means, and how to check it yourself.

The short version

When you pick a file, the browser gives JavaScript a File object that points at bytes on your disk. Every PrismFile tool reads those bytes into memory in the tab, does its work there, and creates a new Blob for you to download. There is no upload step, no queue, and no copy of your file on a server — because there is no server-side component to receive one. The site is static HTML, CSS and JavaScript files.

What is stored, and for how long

  • Working memory: files live in JavaScript memory and Canvas buffers. Closing or refreshing the tab discards them. Nothing is written to disk unless you press a download button.
  • Aggregate counts: an event name such as tool_open is counted in this browser's localStorage so the site can be honest about what is used. No filename, no file content, no text and no colour value is ever included.
  • No cookies are set by the site itself, and no third-party script is loaded.

Verify it yourself

  1. Open any tool page, for example Merge PDF.
  2. Open DevTools (F12 or ⌘⌥I) and switch to the Network tab. Press the clear button.
  3. Add a real file and run the tool. Watch the request list.
  4. You will see no request carrying your file. The only entries are the static assets the page already loaded.

A second check: turn off your network connection after the page has loaded, then run the tool. It still works, because the work was never dependent on a connection.

What local processing cannot do

Running in the tab is a privacy property, not a magic upgrade. It means the tool is bounded by your device's memory and by what the browser can decode. It cannot recover text from a scanned page (that is OCR), it cannot open an encrypted PDF without the password, and it cannot make a 400 MB document behave like a 4 MB one. Where a tool has such a limit, the tool page states it rather than hiding it behind a generic “processing…” spinner.

Why this architecture was chosen

File utilities are usually the place where people hand over the most sensitive documents they own — contracts, ID scans, medical letters, payslips. A tool that needs an upload to work creates a copy you cannot see, cannot audit, and cannot delete. Doing the work in the tab removes that copy from existence. It also makes the tool faster for small files, because there is no round trip.
